Out-of-band policy enforcement for OS computer-use models

Inspect screen pixels before autonomous agents execute mouse and keyboard events.

Autonomous agents (Claude Code, OpenAI Operator, Browser-Use, OSWorld) can execute arbitrary desktop actions. When an agent experiences indirect prompt injection or coordinate hallucination, its declared tool call may claim a benign operation while its cursor targets a destructive dialog.

OpticWall intercepts the event stream at the window server layer, captures the framebuffer directly under the target coordinates, runs an on-device quantized Vision Transformer in ~140ms on CPU, and drops the action if destructive patterns are identified.

Technical Specification

How OpticWall enforces policy out-of-band

Software-only guardrails trust the LLM to report its own behavior accurately. When an agent is confused by multi-modal layout shifts or compromised by prompt injection, its internal chain-of-thought diverges from what is physically rendered on screen.

01 / CAPTURE HOOK

Low-latency framebuffer tap

Before an OS mouse click or keyboard sequence reaches the target window, the input filter grabs a localized 448x448 pixel patch around the cursor using native OS compositors (DXGI Desktop Duplication, ScreenCaptureKit, or X11 SHM). Latency: <14ms.

02 / VISUAL INFERENCE

Local Vision Transformer

An INT8 quantized Vision Transformer classifies the rendered UI elements against trained destructive classes: cloud infrastructure teardown, unconfirmed billing, credential exfiltration, and disk format routines. Runs in ~140ms on modern CPUs.

03 / CIRCUIT BREAKER

Deterministic event drop

If the risk score exceeds the configured threshold, the input event is discarded before reaching the application. The offending agent process is sent a freeze signal (SIGSTOP), and a forensic snapshot is saved to local disk for audit review.

Architecture Details

Frequently Asked Technical Questions

How does OpticWall intercept clicks without installing kernel drivers?

OpticWall operates in user-space using standard OS accessibility and event tap APIs (CGEventTap on macOS, SetWindowsHookEx(WH_MOUSE_LL) on Windows, and X11/XInput event filtering on Linux). For browser-specific and MCP-level agents, it also exposes a standard MCP tool wrapper and Chrome extension content script that hook action dispatches before execution.

Why is visual verification necessary if agents have prompt guardrails?

Prompt guardrails only evaluate text tokens generated by the LLM. If a model encounters adversarial content on a webpage or in a repository (such as hidden CSS or white-on-white text), indirect prompt injection can instruct the model to execute destructive clicks while emitting benign chain-of-thought tokens like "Indexing local workspace". The screen pixels represent ground truth of what the application will execute.

What happens when a dangerous action is intercepted?

When the visual risk score meets or exceeds the policy threshold (default 0.50), the input event is dropped immediately so the application never receives the click. OpticWall dispatches a pause signal (SIGSTOP) to the agent's process ID, logs a high-resolution screenshot to ~/.opticwall/incidents/, and displays a native notification allowing you to resume or kill the agent.

Does OpticWall send screenshots or telemetry to external servers?

No. OpticWall is completely self-contained. Both the screenshot capture and the ONNX Vision Transformer model execute in local system memory. The daemon has zero outbound network calls, telemetry trackers, or external API dependencies.

How can I customize policy thresholds and blocked UI categories?

Policies are defined in standard YAML at ~/.opticwall/policy.yaml. You can set custom thresholds per category (destructive actions, financial transactions, credential views) or whitelist specific application window titles and domains.
